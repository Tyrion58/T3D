![Overview](./img/T3D.png)
<b>Overview</b>: We propose **T3D** (Trajectory Self-Distillation via Direct Discriminative Optimization), a trajectory self-distillation framework designed to enable **high-quality few-step inference** for Diffusion Large Language Models (DLLMs).

While DLLMs provide strong potential for parallel token generation, they often suffer from severe quality degradation when the number of denoising steps is aggressively reduced.
T3D addresses this challenge by distilling **generative trajectories** from a full-step teacher model, significantly narrowing the performance gap between few-step and full-step decoding.

## Key Ideas
- **Trajectory Self-Distillation:** The student matches the teacher's whole generative trajectory instead of only its final output, which reduces the token-factorization error that breaks few-step decoding.

- **Direct Discriminative Optimization (DDO):** A reverse-KL-style objective drives the student toward the teacher's high-probability modes, giving sharper predictions on reasoning tasks.

- **Path-Consistency Regularization:** Tokens decoded early in a block receive more weight, because their errors propagate to every later step.

- **Label-Free Training:** The student learns entirely from trajectories generated by the model itself; no external labels are needed.

## Results

Accuracy (%) of SDAR-4B-Chat before and after T3D, as reported in the paper (decoding block size 4). Math and code benchmarks use separate students, distilled on MATH and PrimeIntellect trajectories respectively.

**Static decoding.** One token per step is full decoding; two and four tokens per step halve and quarter the number of denoising steps.

| Tokens per step | Model | MATH500 | GSM8K | MBPP | HumanEval |
| :---: | :--- | :---: | :---: | :---: | :---: |
| 1 | SDAR-4B-Chat | 68.00 | **89.84** | **58.60** | 71.95 |
|   | + T3D | **70.00** | 89.31 | 54.20 | **73.78** |
| 2 | SDAR-4B-Chat | 54.40 | 78.77 | 34.20 | 49.39 |
|   | + T3D | **60.00** | **83.85** | **38.80** | **51.83** |
| 4 | SDAR-4B-Chat | 13.80 | 41.09 | 14.00 | 18.29 |
|   | + T3D | **47.80** | **69.90** | **22.60** | **23.78** |

**Dynamic decoding.** Tokens are accepted once their confidence exceeds 0.9, so the number of steps adapts to the input. TPS is throughput in tokens per second.

| Benchmark | SDAR-4B-Chat TPS | SDAR-4B-Chat Acc | + T3D TPS | + T3D Acc |
| :--- | :---: | :---: | :---: | :---: |
| MATH500 | 657.72 | 39.00 | **791.23** | **49.40** |
| GSM8K | 580.60 | 61.56 | **843.05** | **72.40** |
| MBPP | 262.66 | 23.40 | **313.18** | **23.60** |
| HumanEval | 175.48 | **33.54** | **222.68** | 29.27 |

The paper has the full comparison: SDAR-1.7B-Chat, LLaDA-8B-Instruct, block size 8, and other few-step methods. This repository provides the T3D pipeline for the SDAR family (trajectory rollout, training, evaluation).

### 3. (Optional) Paths

All commands are run from the repository root. Defaults can be redirected with environment variables:

| Variable | Purpose | Default |
| --- | --- | --- |
| `T3D_DATA_DIR` | datasets and training files | `<repo>/data` |
| `T3D_OUTPUT_DIR` | rollouts, results, checkpoints | `<repo>/artifacts` |
| `T3D_CACHE_ROOT` | Triton / Torch extension cache (use a local disk) | `~/.cache/t3d` |

## Quick Start

Evaluate the released checkpoint on MATH500 with two tokens per step:

```bash
huggingface-cli download Tyrion279/SDAR-4B-Chat-t3d-math --local-dir checkpoints/SDAR-4B-Chat-t3d-math
(cd data && python download_data.py --dataset MATH500)

python eval.py config=configs/eval/eval_sdar.yaml \
    evaluation.checkpoint_path=checkpoints/SDAR-4B-Chat-t3d-math \
    evaluation.eval_dataset=MATH500 \
    evaluation.data_type=math \
    rollout.block_size=4 \
    rollout.denoising_steps_per_block=2
```

The accuracy should be close to 60% (60.00 in the paper). It is written to `artifacts/eval/results/`, together with decoding statistics. One 40 GB GPU is enough for SDAR-4B-Chat.

## Data Preparation

Dataset JSON files live under `data/`. Download them with:

```bash
cd data
python download_data.py --dataset MATH_train
python download_data.py --dataset MATH500
cd ..
```

Available datasets: `MATH_train`, `PrimeIntellect` (training prompts) and `MATH500`, `GSM8K`, `MBPP`, `HumanEval` (evaluation).

## Training

T3D needs no labels. The teacher answers the training prompts, its decoding trajectory is recorded, and the student is distilled on those trajectories in three stages:

1. Rollout trajectory generation
2. Trajectory preprocessing
3. T3D training

To train SDAR-4B-Chat on MATH you can skip the first two stages and use the [released trajectories](#using-the-released-trajectories).

### Stage 1 — Rollout (Trajectory Generation)

Rollout and evaluation read the model from a local directory, so download the teacher first:

```bash
huggingface-cli download JetLM/SDAR-4B-Chat --local-dir /path/to/SDAR-4B-Chat
```

```bash
python sample/sdar_sample.py config=configs/rollout/sdar_sample.yaml \
    evaluation.checkpoint_path=/path/to/SDAR-4B-Chat \
    evaluation.eval_dataset=MATH_train \
    evaluation.data_type=math \
    rollout.block_size=4 \
    rollout.denoising_steps_per_block=4 \
    rollout.max_token=2000 \
    rollout.temperature=0.1 \
    rollout.top_p=1.0 \
    rollout.top_k=0 \
    rollout.remasking_strategy="low_confidence_static"
```

The rollout is written to `artifacts/rollout_sdar/temp_data/`.

### Stage 2 — Preprocess Trajectories

Copy the rollout file into `data/`:

```bash
cp artifacts/rollout_sdar/temp_data/outputs-eval-SDAR-4B-Chat-dspb4-bs4-MATH_train.json \
   data/SDAR-4B-Chat-MATH_train.json
```

Then preprocess:

```bash
python data/rename_key.py --model_name SDAR-4B-Chat --dataset MATH_train
```

This produces `data/SDAR-4B-Chat-MATH_train_renamed.json`, the file referenced by `dataset.optimization_data` in the training config.

### Using the Released Trajectories

The following writes the same training file from the released SDAR-4B-Chat trajectories:

```bash
python - <<'EOF'
import json
from datasets import load_dataset

rows = load_dataset("Tyrion279/SDAR-4B-Chat-MATH-Trajectories", split="train")
data = [{"question": r["question"], "answer": [r["answer"]], "step_map": [r["step_map"]],
         "response_length": [r["response_length"]]} for r in rows]
json.dump(data, open("data/SDAR-4B-Chat-MATH_train_renamed.json", "w"))
EOF
```

### Stage 3 — Training (T3D)

```bash
wandb login   # optional

accelerate launch \
  --num_machines 1 \
  --machine_rank 0 \
  --main_process_ip 127.0.0.1 \
  --main_process_port 8889 \
  --config_file accelerate_configs/1_node_8_gpus_deepspeed_zero1.yaml \
  train/self_ddo_sdar_full.py \
  config=configs/train/ddo_sdar_full_self.yaml
```

Training loads the base model by its Hub id. Checkpoints are saved under `artifacts/experiments/<model>/<data_type>/<project>/<timestamp>/ckpt/`. The reference model is refreshed from the student every `training.round_interval` global steps, and a checkpoint named `optimized-round<N>-step<S>` is written at each refresh.

| Setting | Config |
| --- | --- |
| SDAR-4B-Chat, math | `configs/train/ddo_sdar_full_self.yaml` |
| SDAR-4B-Chat, code | `configs/train/ddo_sdar_4b_code.yaml` |
| SDAR-1.7B-Chat, math | `configs/train/ddo_sdar_1_7b_math.yaml` |
| SDAR-1.7B-Chat, code | `configs/train/ddo_sdar_1_7b_code.yaml` |

The configs assume 8 GPUs; with fewer GPUs, scale `training.gradient_accumulation_steps` to keep the effective batch size and pick the matching file in `accelerate_configs/`.

## Evaluation

`eval.py` runs the rollout, executes generated code when `data_type=code`, and scores the answers:

```bash
python eval.py config=configs/eval/eval_sdar.yaml \
    evaluation.checkpoint_path=/path/to/checkpoint \
    evaluation.eval_dataset=MATH500 \
    evaluation.data_type=math \
    rollout.block_size=4 \
    rollout.denoising_steps_per_block=1 \
    rollout.temperature=0.1
```

The number of tokens decoded per step is `rollout.block_size / rollout.denoising_steps_per_block`. Results are appended to `artifacts/<experiment.project>/results/`, together with decoding statistics (average denoising steps, tokens per step, throughput and latency).

| Scenario | Overrides |
| --- | --- |
| Full decoding | `rollout.block_size=4 rollout.denoising_steps_per_block=4` |
| Dynamic decoding | `rollout.remasking_strategy=low_confidence_dynamic rollout.dynamic_threshold=0.9 rollout.denoising_steps_per_block=4` |
| Greedy decoding | `rollout.temperature=0` |
| Code benchmarks | `evaluation.eval_dataset=MBPP evaluation.data_type=code` (or `HumanEval`) |

The sampler starts one worker on every visible GPU; select GPUs with `CUDA_VISIBLE_DEVICES`, and use a single GPU when measuring throughput.

## FAQ

**Do I need a separate checkpoint for each block size?**
No. Training uses a fixed block size of 8 (`training.block_size`). The decoding block size is an evaluation-time hyperparameter (`rollout.block_size`), so one checkpoint covers all of them.

**Is one student trained for both math and code?**
No. The math and code students are trained separately, on MATH and PrimeIntellect trajectories.

**How much compute does training need?**
The configs target 8 × A100-40GB with DeepSpeed ZeRO-1 and bf16. For SDAR-4B-Chat, the paper reports about 1.5 hours for trajectory collection and about 8 hours for T3D training.

**Can I pass a Hub model id to rollout or evaluation?**
No. The inference engine reads weights from a local directory, so download the model first with `huggingface-cli download`. Training accepts a Hub id.
